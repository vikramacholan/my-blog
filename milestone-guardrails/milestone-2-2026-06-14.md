# Milestone 2: Implement Persistent Blog Post View Counter via Upstash

## Agent Instructions
**CRITICAL:** Before generating any code for this milestone, you MUST read and strictly adhere to the rules defined in `.agents/rules/upstash-redis.md`. Do not write code using deprecated Vercel KV packages.

## Objective
Implement a persistent view counter for individual blog posts using Upstash Redis. The view count must persist across deployments, handle concurrent visits safely via atomic increments, and display seamlessly in the existing blog post hero UI next to the author's name.

## Requirements & Steps

1. **Dependencies & Environment Setup**
   - Install the official package: `npm install @upstash/redis`.
   - Verify that `.env.local` contains `viklab_upstash_redis_KV_REST_API_URL` and `viklab_upstash_redis_KV_REST_API_TOKEN` (pulled using `vercel env pull`).

2. **Tracking Implementation (Backend)**
   - Create a Next.js Route Handler at `src/app/api/views/[slug]/route.ts`.
   - Implement a `POST` method that accepts the blog post slug parameter.
   - Atomically increment the view count using `await redis.incr(...)` matching the `pageviews:blog:{slug}` key convention.
   - Return the newly updated count as a JSON response.

3. **Tracking Trigger (Client)**
   - Create a lightweight, client-side tracking component (e.g., `<ViewTracker slug={slug} />`).
   - Use a `useEffect` hook to fire a `POST` request to the tracking API endpoint precisely once when the blog post component mounts on the client browser.
   - Embed this tracker component within the main blog post page layout.

4. **UI Integration (Display)**
   - In the Server Component responsible for rendering the blog post hero section, fetch the current view count using `await redis.get(...)`.
   - Ensure a fallback display of `0` if the key returns null or errors out.
   - Inject the retrieved count cleanly into the metadata row next to the author's name ("Vikram").
   - Label the number properly (e.g., "Views" or use a subtle eye icon) matching the existing Tailwind/CSS typography styling.

## Acceptance Criteria
- [ ] `@upstash/redis` package is utilized exclusively for database interactions.
- [ ] Views are incremented using the atomic `incr` command to eliminate race conditions.
- [ ] View counts are completely insulated from Next.js build-time execution and static generation steps.
- [ ] The live count is visually integrated adjacent to the author block in the post header.
- [ ] Database connection issues degrade gracefully to a view count of `0` without breaking the page render.
